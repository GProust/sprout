# The shared specification

What Sprout for Android and Sprout for iOS must agree on, and the vectors that
prove they do.

Everything else in this repository belongs to one platform or the other. This
directory belongs to neither, and that is the point: a household with an Android
phone and an iPhone in it syncs only if both apps read the same bytes the same
way. When they disagree the failure is silent — two phones that never pair, or
pair and then quietly stop merging — which is the worst way for a data-loss bug
to present itself.

- [`wire-format.md`](wire-format.md) — the formats, field by field.
- [`vectors/`](vectors/) — the conformance vectors both test suites read.

## Why the vectors are generated by neither app

[`vectors/generate.mjs`](vectors/generate.mjs) is Node. It shares no code with
the Kotlin or the Swift, so a vector it produces cannot encode either one's
mistake. Vectors generated *from* Android would only ever prove that iOS agrees
with Android — not that both agree with the format written down here.

This is the standard `EncryptedZipTest` already holds itself to: it checks the
key derivation against RFC 6070 and a whole entry against an outside
implementation, rather than against its own output.

The generator is deterministic. Re-running it must leave the working tree clean,
and CI checks that — so a vector cannot be quietly edited to match a change in
behaviour.

```
node spec/vectors/generate.mjs
```

## Changing any of this

A change here is a change to both apps at once, and to every copy of Sprout
already installed.

- **Adding a field** to a payload is safe in both directions: a reader that does
  not know it ignores it, and one that expects it must tolerate its absence.
- **Changing the meaning of an existing field, the framing, or the crypto** is
  not. It needs a format-version bump and a decision record, because a phone
  that has not updated is on the other side of it.
- **Every change lands with its vectors in the same commit.** A vector regenerated
  in a later commit than the behaviour it describes is a window in which CI is
  green and the two apps disagree.
